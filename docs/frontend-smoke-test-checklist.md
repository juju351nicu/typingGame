# Frontend Smoke Test Checklist

## 目的

バックエンドAPI接続前後で、主要導線が壊れていないかを短時間で確認するための手動チェックリストです。

自動E2Eを追加する前段階として、まずは画面遷移、localStorage保存、ランキング反映、ブログ表示の最低限を確認します。

## 事前準備

```bash
npm run dev
```

ブラウザで開くURL:

```text
http://localhost:8081/
```

確認前に必要であれば、設定画面からスコアを初期化します。

## 1. 通常プレイからランキング反映

1. トップページで `Play` を押す。
2. 表示された単語をいくつか入力する。
3. 通常モードの終了条件でゲームを終了する。
4. Result に Score / WPM / 正確率 / 正タイプ数 / ミス数が表示される。
5. `リトライ` を押して、ページリロードなしで Play 前の状態に戻る。
6. サイドメニューからランキング画面へ移動する。
7. 直近のスコアがランキングに表示される。
8. 分析タブで score / wpm / accuracy の推移が表示される。

## 2. タイムアタックからランキング反映

1. 設定画面でゲームルールを `タイムアタック` に変更する。
2. 制限時間を選択する。
3. トップページで `Play` を押す。
4. 残り時間が表示され、カウントダウンされる。
5. 時間切れで Result が表示される。
6. Result にゲームルールと制限時間が表示される。
7. ランキング画面で `タイムアタック` と制限時間フィルターを選択する。
8. 該当スコアと分析タブの推移が表示される。

## 3. スコア初期化とempty表示

1. 設定画面を開く。
2. スコア初期化ボタンを押す。
3. 確認ダイアログが表示される。
4. 初期化を確定する。
5. ランキング画面を開く。
6. スコアがない状態の表示が崩れていない。
7. 分析タブでも empty 表示が表示される。

## 4. テーマ切替

1. 設定画面を開く。
2. 表示テーマを `ダーク` に切り替える。
3. トップページ、ランキング画面、ブログ詳細画面の背景と文字色が崩れていない。
4. 入力欄の文字が読める。
5. ブラウザを再読み込みしてもダークテーマが維持される。
6. 表示テーマを `ライト` に戻す。

## 5. ブログ一覧と記事詳細

1. ブログ一覧画面を開く。
2. 記事一覧が表示される。
3. 任意の記事を開く。
4. Markdown本文が表示される。
5. コードブロックの表示が崩れていない。
6. 前の記事 / 次の記事がある場合、押下して記事が切り替わる。
7. 一覧ページに戻るボタンで元のページ番号へ戻る。

## 6. 公開パス想定のbuild確認

```bash
npm run build
```

確認観点:

- build が成功する。
- chunk size warning が出ない。
- `dist/blog_store` にブログデータがコピーされる。

## 7. GitHub Pagesから本番APIへ接続

前提:

```text
FE: https://juju351nicu.github.io/typingGame/
API: https://api.clipdev.jp
```

1. EC2起動後、未認証の `GET /api/auth/me` が401になることを確認する。
2. GitHub Pagesを開き、ヘッダーにログイン導線が表示されることを確認する。
3. 新しいテスト用メールアドレスでユーザー登録する。
4. 登録後にログイン状態となり、ヘッダーへメールアドレスが表示されることを確認する。
5. DevToolsのNetworkで、`/api/auth/login` と `/api/auth/me` が `https://api.clipdev.jp` 宛てであることを確認する。
6. 認証必須APIに `Authorization: Bearer ...` が付くことを確認する。実JWTは画面共有や記録へ残さない。
7. ページを再読み込みし、sessionStorageのJWTからログイン表示が復元されることを確認する。
8. ゲームを完了し、`POST /api/me/scores` が成功することを確認する。
9. ランキング画面で `GET /api/me/scores` の結果が表示されることを確認する。
10. 「全体ランキング」へ切り替え、`GET /api/rankings` の結果が表示されることを確認する。
11. ログアウト後、JWTがsessionStorageから削除されることを確認する。

確認観点:

- ブラウザのConsoleにCORSまたはMixed Contentエラーが出ない。
- API失敗時もlocalStorageへ保存済みのプレイ結果は消えない。
- JWT期限切れまたは401時にログイン状態が解除され、再ログイン案内が表示される。
