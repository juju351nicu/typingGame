## プロジェクト概要

`Balloon Typing Game` は、Vue 3 + TypeScript + Vite で作成しているタイピングゲームです。

画面下から浮かんでくる風船に英単語が表示され、プレイヤーはその単語を入力して風船を割ります。ゲーム終了後にはスコア、プレイ時間、WPM、正確率、ミス数、ランクなどを表示し、プレイ履歴はブラウザの `localStorage` に保存されます。

現在はフロントエンドのみで完結する構成です。Spring Boot API、JWT ログイン、Docker、PWA などは将来的な拡張候補として残していますが、現時点では「公開して見た人に伝わる完成度」を優先しています。

### GitHub Actions workflow 追加時のエラー

最初に `.github/workflows/deploy.yml` を追加して push しようとした際、以下のエラーが出ました。

```text
refusing to allow a Personal Access Token to create or update workflow `.github/workflows/deploy.yml` without `workflow` scope
```

これは、GitHub の Personal Access Token に `workflow` スコープが付いていないため、GitHub Actions の workflow ファイルを作成・更新できないというエラーです。

対応として GitHub CLI (`gh`) を導入し、GitHub 認証を更新しました。

```bash
brew install gh
gh auth login
gh auth refresh -h github.com -s workflow
```

途中でブラウザに device code を入力する認証がありました。認証後、workflow ファイルを再度追加して push できるようになりました。

### GitHub Pages の Source 設定

GitHub の Pages 設定画面で、`Build and deployment` の `Source` を確認しました。

最初は `Deploy from a branch` が表示されていましたが、GitHub Actions でデプロイする構成にしたため、最終的には `GitHub Actions` を使う形にしました。

### GitHub Pages でのページ遷移エラー

公開直後、トップページは開けても、`/scoresBoard` や `/settingBoard` に直接アクセスすると 404 になる問題がありました。

原因は GitHub Pages が SPA のルーティングを直接解決できないためです。

対策として、GitHub Actions の build 後に以下を実行するようにしました。

```bash
cp dist/index.html dist/404.html
```

これにより、GitHub Pages で直接 URL を開いても Vue Router 側に処理を戻せるようになりました。

### WPM の説明

WPM は `Words Per Minute` の略です。1分あたりに入力できた単語数の目安です。

このアプリでは英単語そのものの数ではなく、一般的なタイピング指標に近づけるため、正しく入力できた文字数を 5 文字で 1 単語として換算しています。

計算イメージは以下です。

```text
WPM = 正しく入力した文字数 ÷ 5 ÷ プレイ時間（分）
```

`TypingPanel.vue` に多くの処理が集まっていたため、まずは安全な範囲で単語処理を composable に切り出しました。

- 表示用単語オブジェクトの生成

追加したテスト:

```text

```

テスト内容:

- 現在表示する単語を生成できる
- 入力済み文字に `correct` / `incorrect` が付く
- 未入力部分は空文字になる
- 入力値が単語の先頭と一致するか判定できる
- 破裂中の単語は一致判定から除外される
- 入力完了した単語の位置を返せる
- 単語状態に応じた表示クラスを返せる
- 単語リストを破壊せずにシャッフルできる

### composable 化後に発生したバグ

composable 化後、ゲームが途中で早く終わるバグが発生しました。

最初は難易度「難」の風船速度が速すぎるためかと考えましたが、ユーザー確認により、難易度に関係なく「風船がまだ上に到達していないのにリザルトが表示される」ことが分かりました。

最終的な原因は、入力ハイライト処理で `currentWords` 内の単語オブジェクトを作り直してしまっていたことです。

その結果、以下の問題が起きていました。

1. 正しく入力された風船を `targetWord` として保持
2. 破裂アニメーション中に `applyCharacterFeedback` が単語オブジェクトを新しく作り直す
3. `setTimeout` 後に `targetWord` と同じ参照の単語を探して削除しようとする
4. 参照が変わっているため見つからない
5. 破裂済みの見えない単語が内部データに残る
6. 見えない単語が上端判定に引っかかる
7. まだ画面上の風船が上に到達していないのにゲーム終了する

修正内容:

- `applyCharacterFeedback` で単語オブジェクトを作り直さず、既存オブジェクトの `classList` だけ更新するように修正
- 破裂中の風船は上端到達判定から除外
- 難易度の速度変更は原因ではなかったため戻した

この修正後、ユーザー確認で「直ってました」と確認できました。
