### 詳細

この日は、アプリをローカルで動くだけの状態から、GitHub Pages で公開できる状態へ進めました。

まず、ブログ記事一覧用の JSON に重複があったため、不要な重複データを削除しました。

その後、Vite + Vue Router 構成のアプリを GitHub Pages に公開するため、Vite の `base` 設定を追加しました。

GitHub Pages ではリポジトリ名付きの URL になります。

```text
https://juju351nicu.github.io/typingGame/
```

そのため、build 時だけ `/typingGame/` を base path として使うように設定しました。

### GitHub Pages 対応

`vite.config.js` に GitHub Pages 用の base path を追加しました。

```js
base: command === "build" ? "/typingGame/" : "/",
```

ローカル開発時は `/` のまま動かし、本番 build 時だけ `/typingGame/` に切り替えることで、ローカルと本番の両方で動作するようにしました。

### Vue Router 対応

Vue Router の history に `import.meta.env.BASE_URL` を渡すようにしました。

これにより、GitHub Pages 上でも `/typingGame/scoresBoard` のような正しい URL でページ遷移できるようになりました。

### GitHub Actions 対応

`.github/workflows/deploy.yml` を追加し、`master` ブランチへ push すると自動で以下の処理が走るようにしました。

1. リポジトリを checkout
2. Node.js をセットアップ
3. `npm ci`
4. `npm run build`
5. `dist` を GitHub Pages にデプロイ

### 発生した問題と対応

#### workflow 権限エラー

GitHub Actions の workflow ファイルを push しようとした際、Personal Access Token に `workflow` scope がなく、push が拒否されました。

```text
refusing to allow a Personal Access Token to create or update workflow
without workflow scope
```

GitHub CLI をインストールし、`workflow` scope を追加して対応しました。

#### Linux build でのファイル名エラー

GitHub Actions 上で build した際、以下のようなエラーが発生しました。

```text
Could not load src/stores/blogPosts
```

原因は、Git 上では `BlogPosts.ts` として管理されていた一方、import 側では `blogPosts` と小文字で参照していたことでした。

macOS では大文字小文字を区別しない環境が多いためローカルでは動いていましたが、GitHub Actions の Linux 環境では別ファイルとして扱われ、build が失敗しました。

`src/stores/BlogPosts.ts` を `src/stores/blogPosts.ts` にリネームし、import とファイル名を一致させました。

#### GitHub Pages 上のページ遷移エラー

サイドメニューのリンクが通常の `href="/"` になっていたため、GitHub Pages 上で `/typingGame/` が抜け、以下のような URL に飛んで 404 になりました。

```text
https://juju351nicu.github.io/scoresBoard
```

`href` ではなく Vue Router の `:to="{ name: ... }"` を使うように変更し、GitHub Pages の base path を保ったまま遷移できるようにしました。

### 確認したこと

- `npm run build` が通ること
- GitHub Actions が成功すること
- GitHub Pages に公開されること
- 公開 URL でページ遷移できること

## タイマー停止バグ修正

### 発生した問題

リザルト画面が表示されたあとも、背面のストップウォッチ表示が進み続けていました。

リザルト画面に表示されるプレイ時間は保存時点で止まっていましたが、画面裏の `Timer` コンポーネントだけが動き続けている状態でした。

### 原因

ゲームオーバー後でも `Shift` キー操作によって `startTimer()` を再度呼べる状態が残っていました。

また、`stopTimer()` 後に `timerId` が `null` に戻っていなかったため、状態管理としても不十分でした。

### 対応

- `stopTimer()` 後に `timerId.value = null` を追加
- ゲームオーバー時は先にタイマーを停止してからスコア保存
- `isGameOver` 中は `Shift` キーでタイマーを再開しないように条件追加

### 確認

ゲーム終了後、背面のタイマー表示も停止することを確認しました。

### WPM / 正確率 / ミス数の追加

リザルト画面に以下を追加しました。

- WPM
- 正確率
- ミス数

### 実装内容

`TypingPanel.vue` で入力状況を記録するようにしました。

- 入力した文字数
- 正しく入力できた文字数
- ミスした文字数

入力文字数は、入力欄の文字数が増えたタイミングで加算します。

ミス数は、現在表示されているどの単語の先頭にも一致しない入力になった場合に加算します。

正しく入力できた文字数は、単語を正しく入力して風船を割ったタイミングで、その単語の文字数を加算します。

### 計算ロジック

WPM と正確率は `src/utils/util.ts` に関数として追加しました。

WPM は、正しく入力できた文字数を 5 文字で 1 word として換算し、プレイ時間から算出します。

正確率は、入力文字数とミス数から算出します。

### 既存データへの配慮

すでに localStorage に保存されている過去スコアには、WPM、正確率、ミス数が存在しません。

そのため、`GameScore` の追加項目は optional にし、過去データが残っていても画面が壊れないようにしました。

### テスト追加

Vitest に以下のテストを追加しました。

- `calculateWpm`
- `calculateAccuracy`
- `getResultRank`
- `getResultRankColor`

これにより、リザルト画面で使う計算処理の最低限の正しさを確認できるようにしました。

### ランキング画面の情報拡張

リザルト画面に WPM、正確率、ミス数を追加したことで、保存されたプレイ履歴にも同じ情報を表示できるようになりました。

そのため、ランキング画面にも以下の項目を追加しました。

- ランク
- WPM
- 正確率
- ミス数

これにより、単純なスコア順位だけでなく、どれくらい速く、どれくらい正確に入力できたかも比較できるようになりました。

過去に保存されたスコアには WPM、正確率、ミス数が入っていない場合があるため、値が存在しない場合は `-` を表示するようにし、既存データでも画面が壊れないようにしました。

### ランク判定ロジックの共通化

リザルト画面とランキング画面の両方でランクを表示するようになったため、ランク判定処理を `src/utils/util.ts` に移動しました。

追加した関数は以下です。

- `getResultRank`
- `getResultRankColor`

これにより、ランクの基準や色を変更したい場合でも、複数のコンポーネントを個別に修正する必要がなくなりました。

### 入力中の文字ハイライト / ミス表示の改善

プレイ中に、入力がどの風船に対応しているか分かりやすくするため、入力中のフィードバックを改善しました。

実装した内容は以下です。

- 入力中の文字列と一致している風船を強調
- 正しく入力できている文字を明るく表示
- 間違っている文字を赤系で強調
- どの単語の先頭にも一致しない入力になった場合、入力欄を赤く表示
- ミス時に入力欄と風船へ短い揺れアニメーションを追加

これにより、プレイヤーが「今の入力が合っているか」「どこでミスしたか」を視覚的に判断しやすくなりました。
